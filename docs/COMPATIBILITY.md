# JavaScript SDK compatibility

This unofficial Ruby client targets the official `@typesafe-ai/sdk` **0.7.0** release,
commit [`b844cd1aca12855a5d24a2df52a1401c86e7d37a`](https://github.com/typesafe-ai/typesafe-sdk-js/tree/b844cd1aca12855a5d24a2df52a1401c86e7d37a).
Audit date: 2026-10-16. This is a tested compatibility target, not a claim of endorsement
or a guarantee about future API changes.

## What is covered

| Surface | Ruby behavior |
| --- | --- |
| Endpoints | `POST /v1/systemone`, `GET /v1/models` |
| Defaults | `jev-latest`, 10-second attempt timeout, two retries |
| Questions | Noul, choice, ordered score criteria, and box; structured instructions/state and nullable choice descriptions |
| Images | `image`, `Image.from_base64`, images in content, `with_assets`/`join_assets` text, named `assets:`; multipart encoding, part names, content types, and reference validation |
| Compression | zstd for bodies of 1 KiB or more (UTF-8 bytes), `compression: false`, protected `Content-Encoding`, same bytes on every retry |
| Serialization | Non-finite floats sent as `"NaN"`, `"Infinity"`, `"-Infinity"`; the request is copied when the call starts |
| Configuration | Explicit settings override trimmed environment values |
| Retries | 408, 429, 500–599; connection and timeout failures independently configurable |
| Server delays | Fractional milliseconds/seconds, HTTP dates, maximum delay and jitter |
| Headers | Case-insensitive overrides; protected auth, content type, SDK and retry headers |
| Errors | HTTP subclasses, validation messages, request IDs, connection/timeout/cancellation errors |
| Transport | Timeout includes full body delivery; cancellation interrupts an active attempt and backoff; truncated bodies are retried |
| Results | Typed answers (including box answers and nullable usage), `to_h` with unmodeled fields; model cards; `with_response: true` for HTTP metadata |
| Extension fields | `extra_body:` forwards additional JSON fields without overriding named arguments |

The checked-in `spec/fixtures/js-0.7.0.json` was generated by executing the published
JavaScript package, rather than by copying expected output from the Ruby implementation.
`parity_spec.rb` compares question JSON, request payloads (including non-finite numbers),
multipart requests and parts with images in content, text, and named assets, `withAssets.join`
text, asset validation messages, base64 decoding, compression thresholds, metadata, error
mapping/messages, complete answer fields (including box answers, fractional scores, and string
rubric keys), retry header parsing, and nullable retry flags. Image references are random, so
the fixture replaces them with stable labels. `http_spec.rb` uses real loopback sockets to exercise behavior
that mocked HTTP adapters cannot verify. Other specs cover Ruby configuration and logging.
Known upstream bugs are corrected explicitly in the comparisons; the fixtures retain the
original JS behavior for those cases.
See the [issue-by-issue audit](UPSTREAM_ISSUES.md) for every upstream issue reviewed.

To regenerate the fixtures with Node.js 22.15 or newer, unpack the official package
(`npm pack @typesafe-ai/sdk@0.7.0`, or the asset from the
[GitHub release](https://github.com/typesafe-ai/typesafe-sdk-js/releases/tag/v0.7.0)) and run:

```sh
node script/generate_parity_fixtures.cjs /path/to/package > spec/fixtures/js-0.7.0.json
bundle exec rake
```

## Intentional Ruby differences and limits

- Images: Ruby accepts a binary `String`, a `Pathname` (read when the request is sent, like a
  JavaScript `Blob`), or an IO (read immediately, since it may not be readable twice). Ruby has
  no tagged template literals, so `with_assets(*parts)` joins text and images given as separate
  arguments, converting other values with `to_s` (`nil` becomes `""`, as in interpolation; the
  JavaScript template writes `null`). A Hash or Array part is written with `to_s`, which includes
  the references of images inside it, so those images are attached; JavaScript writes
  `[object Object]` and attaches none. `join_assets` defaults to `","`, as `withAssets.join` does.
- `assets:` must be a Hash of nonempty names to images; Ruby checks this before sending.
  A request containing a cycle raises `TypeSafeError`; JavaScript raises a `TypeError`.
- Compression needs the optional `zstd-ruby` gem; it is detected once per process, as JS
  detects Node.js zstd support. `compression:` accepts `:zstd`, `"zstd"`, or `false`, and
  `client.compression` returns `:zstd` or `false`.
- JS 0.7.0 returns rejected promises instead of throwing for invalid requests. Ruby calls are
  synchronous, so invalid requests and options raise `TypeSafeError` from the call, before any
  image is read or request is sent.
- Ruby keeps its 0.6.0.1 validation messages. JS 0.7.0 adds similar checks for nil state and
  empty noul questions with its own wording, and both now reject non-Hash noul criteria.

- Since 0.6.0.1, Ruby validates API keys without echoing their contents and rejects reported
  API-invalid state/question shapes locally. Score levels must be non-nil and number 2–10;
  choice options must number 1–255; noul requires instructions or an outcome description;
  state must be a string, object, array, or image; question names cannot be empty.
  Builders and raw question hashes use the same checks. This intentionally tightens the
  JS 0.7.0 behavior, which still accepts nil score levels and unbounded score/choice sizes; local validation is not a complete server schema validator.
- Blank retry headers fall back to configured backoff (or another valid delay header).
  JS 0.7.0 still treats blanks as zero. Literal zero remains valid in Ruby.
- Debug logs fully mask `x-api-key` and keep only an alphabetic authorization scheme followed
  by a credential (upstream #18, unchanged in JS 0.7.0). Cloudflare HTML error pages get a
  message naming the edge block and `cf-ray` ID (upstream #15).
- HTTP 402, 409, and 413 have `PaymentRequiredError`, `ConflictError`, and
  `PayloadTooLargeError` subclasses. Existing `APIError` rescue clauses still catch them.
- Methods/options use snake_case. `timeout:` is in **seconds**; retry settings ending in
  `_ms` remain milliseconds. `retry_policy:` corresponds to JavaScript's `retry` option.
- Calls are synchronous. There is no JavaScript `Promise`, `AbortController`, or compile-time
  inference. Ruby returns answer classes and accepts `Typesafe::SDK::Signal` for cancellation.
- `with_response: true` returns `.data`, `.response`, and `.request_id`. The response exposes
  `.status`, `.headers`, and an already parsed `.body`; it is not a Fetch response or stream.
  Non-2xx responses still raise typed errors. Unlike JavaScript's `asResponse()`, these
  resource methods always construct typed results; there is no unparsed Fetch body API.
- `result[:question]` and `result["question"]` are both supported. `result.answers` itself
  is a Hash with string keys, as received in JSON.
- The noul builder serializes omitted criteria as JSON null; upstream omits the property.
  Both are accepted by the upstream question type. Explicit criteria serialize identically.
- The built-in transport opens one connection and one private worker per attempt. It closes
  and joins them on completion, timeout, or cancellation. It does not pool connections or
  implement a fiber-native asynchronous interface. Custom adapters own timeout/cancellation
  enforcement and must implement the documented `HTTP#request` contract.
- Net::HTTP does not follow redirects automatically; a 3xx raises `APIError`. Use the canonical
  API URL. JavaScript Fetch may follow redirects.
- Ruby's HTTP-date parser and JavaScript's Date parser may differ for malformed, non-HTTP dates.
  Standard HTTP dates and the tested numeric forms are covered.

## Live verification

Offline tests do not prove account authentication, current model availability, billing, or
production inference behavior. No live API key was available during this audit, so no live
TypeSafe request was made.

An explicit smoke test checks model listing and the noul, choice, and score answer types with
synthetic input:

```sh
# Set TYPESAFE_API_KEY securely in your environment first.
TYPESAFE_LIVE_TEST=1 bundle exec ruby script/smoke_test.rb
```

This makes one inference request, which may incur normal API charges. It does not retry or
print the API key, input bodies, or full responses. Add `TYPESAFE_LIVE_IMAGES=1` for an account
with image access to also send one image with a box question to `jev-preview`.
